# Config files (Arch + Hyprland, and macOS)

## Introduction

This directory holds the configuration for my https://www.archlinux.org/[Arch Linux]
machines: my shell (https://fishshell.com[fish], with https://www.zsh.org/[zsh] as a
fallback), my terminal (https://ghostty.org[ghostty]), and my Wayland compositor
(https://hyprland.org[Hyprland]) with the https://github.com/noctalia-dev/noctalia-shell[Noctalia]
bar/shell.

It also covers a macOS machine, which shares the shell / terminal / editor layer
and skips everything Linux-specific.

The full step-by-step is in the
https://github.com/Jubijub/arch-config/wiki[arch-config wiki].

Feel free to copy anything here, but use at your own risk.

## Deployment (chezmoi)

These files are managed with https://www.chezmoi.io[chezmoi], which handles both
deployment and the per-machine differences. The source layout uses chezmoi's
conventions (`dot_config/` -> `~/.config`, `*.tmpl` for templated files,
`private_` for 0700 dirs). See
https://github.com/Jubijub/arch-config/wiki/5.Post-installation#deploy-dotfiles-with-chezmoi[the
chezmoi section of the wiki] for the Arch bootstrap, and
https://github.com/Jubijub/arch-config/wiki/12-MacOS[12-MacOS] for the macOS one.

### Machine roles

`.chezmoi.toml.tmpl` asks once for a *role* and stores the answer; no hostnames
are hardcoded anywhere. The role indexes the `roles` table in
`.chezmoidata.yaml`, which is what the templates actually branch on:

[cols="1,4"]
|===
|Role |Machine

|`workstation` |Asus X870e / 9950X3D / RTX 5090, Arch + Hyprland
|`laptop`      |Lenovo Legion Pro 7i Gen 10, Arch + Hyprland
|`wsl`         |Arch on WSL2 (declared, not yet configured)
|`macbook`     |MacBook "Neo", Apple Silicon, macOS
|===

*Add a machine by adding a row to `.chezmoidata.yaml`*, not by adding another
`{{ if eq .machine "..." }}` branch. Templates branch on the capability flags
(`os`, `arch`, `systemfiles`, `desktop`, `sysmon`, `rgb`), never on `.machine`
directly, because an `{{ else }}` that means "workstation" silently hands a new
machine the workstation's monitors, GPU and RGB config -- which is exactly the
bug this table exists to prevent. Where a branch genuinely cannot be
generalised, the final `{{ else }}` calls `fail` instead of falling through.

`.chezmoiignore` validates the stored role on every apply, so a typo or a role
whose declared `os` does not match the real one fails loudly rather than
deploying the wrong tree.

### Notable pieces

* `hyprland.lua` and `noctalia/config.toml` branch on the role (monitors, GPU,
  battery/backlight, system-monitor widgets). Both are ignored entirely where
  `desktop` is false.
* `system/` holds verbatim `/etc` drop-ins that chezmoi can't manage directly (it
  only touches `$HOME`); `.chezmoiscripts/run_onchange_install-system-files.sh.tmpl`
  installs them with `sudo` on `chezmoi apply`, and is a no-op where
  `systemfiles` is false.
* `Brewfile` + `run_onchange_darwin-brew-bundle.sh.tmpl` install the macOS
  package set. The Arch equivalent is still the `pacman -S` commands in the wiki.
* `macos/set-input-sources.swift` + `run_after_darwin-keyboard-layout.sh.tmpl`
  install the `us-altgr-intl` keyboard layout (the macOS counterpart to the
  `us` / `altgr-intl` XKB variant) and make it the default input source in both
  the session and the login window. No-op on Linux.
* `vscode-extensions.txt` + `run_onchange_install-vscode-extensions.sh.tmpl`
  install the VSCode extension set on *both* OSes (extensions are not files, so
  chezmoi cannot manage them the way it manages `settings.json`).
* VSCode's `settings.json` lives at a different path per OS, so the tree carries
  both and ignores the wrong one; both render the shared
  `.chezmoitemplates/vscode-settings.json`.

### Testing a change

Because `os` is a role field rather than `.chezmoi.os`, *any* machine's output
can be rendered from *any* machine -- so a change can be checked against the
other machines before touching them:

[source,shell]
----
git worktree add /tmp/before HEAD
printf '[data]\n machine = "workstation"\n skipRoleOsCheck = true\n' > /tmp/ws.toml
diff <(chezmoi --config /tmp/ws.toml --source /tmp/before/dotfiles \
         execute-template < /tmp/before/dotfiles/<file>) \
     <(chezmoi --config /tmp/ws.toml --source $PWD \
         execute-template < <file>)
----

`skipRoleOsCheck` exists only for this; never set it in a real
`~/.config/chezmoi/chezmoi.toml`. Confirm on the machine itself afterwards with
`chezmoi diff`, which should be empty for a refactor that is meant to change
nothing.

## Tools

### Themes
* Colors: https://github.com/catppuccin/catppuccin[Catppuccin Mocha]
* Font: https://typeof.net/Iosevka/[Iosevka] with the
  https://www.nerdfonts.com/[Nerd Fonts] patch -- `Iosevka NF` for editors and
  `IosevkaTerm Nerd Font Mono` (the Term cut) for terminals, deliberately two
  different families.
* GTK apps are forced dark via `gsettings ... color-scheme prefer-dark` (no theme
  engine -- full GTK theming was given up as too flaky).

### Shell & CLI
* https://fishshell.com[fish] : main shell, with https://github.com/jorgebucaran/fisher[Fisher]
  plugins and https://starship.rs[Starship].
* https://www.zsh.org[zsh] : POSIX-ish fallback, deliberately plugin-free.
* https://github.com/junegunn/fzf[fzf] : fuzzy history / file search.
* https://github.com/sharkdp/bat[bat] : `cat` with syntax highlighting.
* https://github.com/eza-community/eza[eza] : a modern `ls` replacement (colors, git-aware).
* https://github.com/sharkdp/fd[fd] and https://github.com/BurntSushi/ripgrep[ripgrep].
* https://docs.astral.sh/uv/[uv] : Python packaging / venv manager.
* https://wiki.archlinux.org/title/reflector[reflector] : picks the fastest Arch mirrors.

### Desktop
* https://ghostty.org[ghostty] : terminal (ships a corrected Catppuccin Mocha theme).
* https://github.com/noctalia-dev/noctalia-shell[Noctalia] : Wayland bar + shell.
* https://flameshot.org/[Flameshot] : screenshots with editing.

## Layout

`dot_config/` maps to `~/.config`, `dot_zshrc`/`dot_zshenv` to `~/.zshrc`/`~/.zshenv`,
`dot_local/` to `~/.local`. Highlights:

* `dot_config/hypr/hyprland.lua.tmpl` : Hyprland (machine-templated).
* `dot_config/noctalia/config.toml.tmpl` : Noctalia bar (machine-templated).
* `dot_config/ghostty/` : ghostty config + corrected Catppuccin Mocha theme.
* `dot_config/{bat,btop,fish,flameshot,tmux}/`, `dot_config/starship.toml` : CLI tools.
* `Library/Application Support/Code/User/` : VSCode settings on macOS (the
  `dot_config/Code/` copy is the Linux one; only one is ever deployed).
* `dot_config/nvim/` : Neovim config.
* `dot_config/pipewire/` : PipeWire tweaks.
* `dot_config/gtk-3.0/bookmarks` : Nautilus sidebar bookmarks.
* `Pictures/Wallpapers/` : wallpapers (Noctalia's default wallpaper folder).
* `system/etc/` : `/etc` drop-ins (locale, resolvconf, reflector, pacman hooks, and
  the Legion-only `90-hypr-gpu.rules`), installed by the run-script.
* `macos/` : macOS-only helpers that are not `$HOME` files. Currently the Swift
  utility that drives the Text Input Sources API; run from the source tree, never
  deployed.
* `.chezmoidata.yaml` : the machine roles table (see above).
* `Brewfile`, `vscode-extensions.txt` : package / extension lists read by the
  run-scripts. Not deployed to `$HOME`.
